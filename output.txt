### 1. LOAD TEST CONFIG
```java
// SchedulingLoadTest.java
// 2. Seed 8 Judges
.startTime(LocalTime.of(9, 0))
.endTime(LocalTime.of(17, 0))

// 3. Seed 5 Courtrooms
.startTime(LocalTime.of(9, 0))
.endTime(LocalTime.of(17, 0))

// 5. Measure batch run execution with 60-day horizon so most cases are assigned
JobExecution execution = jobLauncherService.launchNightlyReschedulingJob("SCALE_LOAD_TEST", 60);
```
**Explanation for difference:** The previous load test used 10 judges / 10 rooms / 4 slots (40 slots/day). To make schedules realistic (9 AM - 5 PM), it was changed to 8 judges and 5 courtrooms (the bottleneck), resulting in exactly 8 hours × 5 rooms = 40 slots/day capacity over 60 days. The total throughput is mathematically identical, but correctly validates full-day scheduling instead of sparse 4-slot boundaries.

private static final java.time.format.DateTimeFormatter TIME_FORMATTER =
        java.time.format.DateTimeFormatter.ofPattern("dd MMM yyyy, hh:mm a 'IST'");

private String formatInIst(java.time.LocalDateTime ldt) {
    if (ldt == null) return "TBD";
    return ldt.atZone(java.time.ZoneOffset.UTC)
            .withZoneSameInstant(java.time.ZoneId.of("Asia/Kolkata"))
            .format(TIME_FORMATTER);
}
